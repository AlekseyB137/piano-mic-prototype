# Проект: приложение для обучения игре на фортепиано

## Идея
Пользователь выбирает песню. На экране клавиатура и падающие ноты напротив клавиш, у каждой ноты подпись: название ноты, рука (Л/П) и палец (1–5). Пользователь играет на настоящем пианино, приложение слушает через микрофон телефона и проверяет, правильно ли сыграно. Подключения пианино по MIDI НЕТ — только микрофон.

## Платформа (решение принято)
- Основная цель — Telegram Mini App: доступно на iOS, Android и десктопе без установки.
- Тот же код должен работать как обычный сайт в мобильном браузере.
- Позже возможна обёртка в Capacitor для App Store / Google Play.
- Нативное iOS-приложение (Swift + SpriteKit + AVAudioEngine) — запасной вариант, ТОЛЬКО если прототип покажет, что распознавание в WebView Telegram работает плохо.

## Текущий этап
Прототип распознавания звука — проверка главного риска проекта. Падающие ноты, каталог песен и бэкенд пока не делаем.

Состояние (октябрь 2026):
- Прототип собран: свободный режим (YIN + подтверждение удара, запасной спектральный путь по росту
  партиалов для трелей/легато), режим проверки нот/аккордов (гармоники ×1..×4, защита от октав
  вверх/вниз и субгармоник, октавные аккорды), детектор атаки, калибровка шума, отладочная панель
  и отчёт с причинами отброшенных атак. Голос специально не фильтруем (решение пользователя):
  проверка огибающей убрана, т.к. теряла настоящие ноты в быстрой игре.
- Живые результаты (iPhone, Telegram, октябрь 2026; ЦИФРОВОЕ пианино со слышным механическим стуком
  клавиш при нажатии и отпускании — на акустике ещё не проверяли): одиночные ноты C2–B5 ~100%, трели B5/A#5 и
  E5/D#5 (~3–6 нот/с) 12–13 из 13. Известное ограничение (⚠ в стенде): очень быстрая трель
  (170 мс) с заметно более тихой верхней нотой — часть тихих ударов теряется.
- `npm run test:synth` — стенд на синтетических ударах (test/synth-bench.ts). Гонять после ЛЮБОЙ правки
  в src/audio/. Синтетика ловит логические ошибки, но не заменяет тест с настоящим пианино.
- Следующий шаг: тесты на реальном пианино в Telegram на iPhone и Android, разбор отчётов
  («Поделиться отчётом»), подстройка порогов. Найденные на живом звуке ошибки по возможности
  воспроизводить кейсом в стенде.

## Стек
- Vite + TypeScript, без UI-фреймворка на этапе прототипа.
- Web Audio API: getUserMedia + AudioWorklet.
- Высота одиночной ноты: pitchy (McLeod) или YIN.
- Позже: PixiJS для падающих нот, Tone.js / smplr для звука рояля.
- Telegram: telegram-web-app.js (ready, expand, disableVerticalSwipes, requestFullscreen, lockOrientation).

## Ключевые технические принципы
- Проверять, а не распознавать: приложение знает, какие ноты ожидаются, поэтому проверяем энергию на основной частоте и гармониках (×2, ×3, ×4) именно этих нот. Полная полифоническая транскрипция не нужна.
- Защита от октавных ошибок (сравнение с соседними октавами), детектор атаки (spectral flux) для отличия нового удара от затухания.
- Калибровка фонового шума перед игрой; пороги считаются от неё.
- getUserMedia с echoCancellation / noiseSuppression / autoGainControl = false; проверять track.getSettings(), что реально применилось.
- Аудио запускается только по жесту пользователя (iOS).
- Во время проверки не проигрывать ноты, которые должен сыграть пользователь (иначе приложение услышит само себя), либо рекомендовать наушники.
- Режим ожидания (ноты стоят, пока не сыграна нужная) — основной учебный режим: прощает задержку распознавания 50–150 мс.
- Единственный источник времени — AudioContext.currentTime, анимация только читает его в requestAnimationFrame.

## Будущий формат песен
Источник — MusicXML (есть аппликатура <fingering> и разделение на руки). Офлайн-скрипт на Python (music21, pianoplayer для автоаппликатуры + ручная правка) конвертирует в JSON:
{ "pitch": 60, "name": "C4", "start": 1.5, "dur": 0.5, "hand": "R", "finger": 1 }

## Ограничения экрана
Горизонтальная ориентация; на телефоне показываем окно в 2–3 октавы под диапазон песни, а не все 88 клавиш.
